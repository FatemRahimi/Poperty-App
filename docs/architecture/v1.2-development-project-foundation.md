# Development Scope & Project Identity Foundation

**Contract version:** `development-project-contract-0.1.0`  
**Domain version:** `development-domain-0.1.0`  
**Status:** Foundation contracts + completeness adapter.  
**wiredIntoLiveAnalysis:** `false`  
**Live development assessment:** **NOT YET AVAILABLE**

This phase answers:

- what project are we analysing?
- which asset(s) it applies to
- what is existing vs proposed
- what scope is being considered
- which dependencies are known vs unassessed

It does **not** answer cost, viability, planning grant, schedule, completed value, or whether the user should proceed.

## Entity separation

```
PROPERTY ≠ SITE ≠ LAND_PARCEL ≠ BUILDING ≠ UNIT
  ≠ DEVELOPMENT_PROJECT ≠ DEVELOPMENT_SCENARIO ≠ WORK_SCOPE
```

`DEVELOPMENT_SITE` remains an **asset-class / identity kind**, not a project.

Current Finance **What-if** remains a request-scoped finance sensitivity.  
`CURRENT WHAT-IF ≠ DEVELOPMENT_PROJECT ≠ DEVELOPMENT_SCENARIO`.

## Project identity

`createDevelopmentProject` is a proposed body of work. It does not imply:

- planning permission
- ownership
- funding
- feasibility
- cost certainty
- construction commencement (`ACTIVE` ≠ started)

`UNKNOWN` remains a valid project type. Listing-description inference is not authoritative.

## Subjects

A project may link to `PROPERTY`, `SITE`, `LAND_PARCEL`, `BUILDING`, `UNIT`, `DEVELOPMENT_SITE`, `LISTING`, or `SUBJECT`.

Roles: `PRIMARY_SUBJECT`, `AFFECTED_SUBJECT`, `EXISTING_ASSET`, `PROPOSED_ASSET`, `CONTEXT_ONLY`.

Links never claim cadastral, legal, ownership, or permission relationships. One project is not assumed to be one property.

## Scenario vs project

`PROJECT` = persistent identity/container.  
`SCENARIO` = one proposed configuration under that project (`0..N`).

Finance What-if IDs must not be reused as project or scenario IDs.

## Existing vs proposed

`EXISTING` / `PROPOSED` / `ASSUMED` / `UNKNOWN` stay separate.  
Proposed values never overwrite canonical current-property facts.

## Work scope

A scope is user intent (or non-authoritative `MODEL_ASSISTED` inference).  
It does not imply a defect, planning requirement, cost, or schedule.

Free text is not automatically authoritative scope.

## Dependencies

A dependency may be `KNOWN`, `UNRESOLVED`, `NOT_ASSESSED`, `NOT_APPLICABLE`, or `UNAVAILABLE`.

No severity scores. No generic due-diligence checklist.

Planning dependency is created only when conversion / change of use is explicit **and** no planning evidence is attached.  
Physical work on land without a building does **not** demand `BUILDING_CONDITION`.  
No physical work does **not** demand a building survey.

Future domains that may be referenced: IDENTITY, LEGAL_TITLE, PLANNING, ENVIRONMENT, BUILDING_CONDITION, MAINTENANCE_CAPEX, PROJECT_COST, FINANCE, VALUATION.

## Boundaries

| Domain | Rule |
|---|---|
| PLANNING | Owns planning evidence. Project may declare a dependency; it does not conclude permission. |
| LEGAL_TITLE | Independent. Project does not imply ownership or development rights. Still unwired. |
| BUILDING_CONDITION | Observed physical evidence. “Replace roof” ≠ defective roof. Still unwired. |
| ENVIRONMENT | Evidence/context only. No environmental feasibility. |
| COST | User-entered budget remains `USER_INPUT`. Not estimated cost. |
| MAINTENANCE_CAPEX | Future. Condition ≠ intervention ≠ cost. |
| FEASIBILITY | Future. No GDV, residual, margin, IRR, NPV. |
| PROJECT MANAGEMENT | Future. No tasks, Gantt, contractors, procurement. |

## Findings allowed / forbidden

Allowed when a project is supplied: project defined; scope incomplete; multi-subject; proposed use differs from existing; planning dependency unresolved; no scenario selected.

Forbidden: viable; should be approved; conversion is feasible; profitable; low risk; works should proceed.

## Privacy

`proposedDevelopment`, `projectScope`, and `developmentScenario` are private fact types.  
Shared property identity must not expose another user’s project.  
Reuse existing owner/admin access helpers when persistence is later added.

## Live wiring

PLANNING and ENVIRONMENT remain the only live specialised domains.  
LEGAL_TITLE and BUILDING_CONDITION remain foundation-only.  
DEVELOPMENT is not attached to `assemblePropertyIntelligenceReport`.
