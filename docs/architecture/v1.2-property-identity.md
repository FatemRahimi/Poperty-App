# Property Identity & Asset Classification

**Status:** Live-safe foundation on `property-intelligence-kernel-1.0.0`  
**Classification version:** `asset-classification-1.0.0`  
**Legacy compatibility:** `legacy-residential-compatibility-1.0.0` (temporary, explicit, not `UNKNOWN = RESIDENTIAL`)

This layer answers: **what kind of asset is this?**  
It does not value commercial, industrial, agricultural, land, or development assets.

## Canonical class

`RESIDENTIAL` | `COMMERCIAL` | `INDUSTRIAL` | `AGRICULTURAL` | `LAND` | `DEVELOPMENT_SITE` | `MIXED_USE` | `UNKNOWN`

`UNKNOWN` is valid. It is not an error and is not secretly residential.

## Classification state

| State | Meaning |
|---|---|
| `DECLARED` | First-party / admin / explicit property input |
| `AUTHORITATIVE` | Source whose contract establishes the class |
| `INFERRED` | Weaker evidence; requires provenance and categorical confidence |
| `UNKNOWN` | Insufficient evidence |

Confidence is categorical (`stated`, `low`, `medium`, `high`) or `null`. Percentages are not fabricated.

## Persistence

Single source of truth: `asset_classifications` (listing **or** subject).  
Audit: `asset_classification_events`.  
`properties.property_type` / `property_category` remain marketplace fields. They do not replace this table.

## Mapping

Only `EXACT_SAFE_MAPPING` may be persisted (`property_category` or type words that **are** the class: `residential`, `commercial`, `industrial`, `agricultural`, `land`, `development_site`, `mixed_use`).

Dwelling types (`flat`, `terraced`, `office`, `warehouse`, …) are `CONDITIONAL_MAPPING` and stay `UNKNOWN`.

## Live analysis gate

| Class | Residential valuation / rental |
|---|---|
| `RESIDENTIAL` | Current methodology (`RESIDENTIAL_SUPPORTED`) |
| `UNKNOWN` | Current product may run as `LEGACY_RESIDENTIAL_COMPATIBILITY` — does **not** classify the asset as residential |
| Other classes | `NOT_SUPPORTED_FOR_ASSET_CLASS` — no substitute valuation is invented |

## UPRN

UPRN remains a useful addressable-property key. It is not the asset class, not a land parcel, not a title, and not every future entity.

Canonical subject identity (`canonical-subject-identity-1.0.0`) persists source address separately from canonical PAON/SAON/postcode/UPRN. States: `VERIFIED_EXACT`, `SOURCE_ASSERTED`, `USER_DECLARED`, `INFERRED`, `UNRESOLVED`. Inferred is never verified. Multiple UPRN candidates stay unresolved. Building identity is not unit identity.

Official MHCLG EPB UPRNs, if later acquired from a unique exact certificate match, remain `SOURCE_ASSERTED` / `OFFICIAL`, not `VERIFIED_EXACT` and not title identity. See `docs/architecture/decisions/physical-property-identity-source.md` (`NOT_IMPLEMENTED`).
