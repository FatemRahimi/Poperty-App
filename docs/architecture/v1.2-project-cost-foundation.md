# Project Cost & Cost Evidence Foundation

**Contract version:** `project-cost-contract-0.1.0`  
**Domain version:** `project-cost-domain-0.1.0`  
**Status:** Foundation contracts + completeness adapter.  
**wiredIntoLiveAnalysis:** `false`  
**Live project-cost assessment:** **NOT YET AVAILABLE**

This phase answers:

- what cost evidence exists
- which project / scenario / scope it applies to
- whether it is a quote, budget, actual, benchmark, assumption, or derived value
- unit and price-base date
- inclusions / exclusions
- what can be deterministically subtotalled
- what remains unknown

It does **not** answer what the project will cost, whether a quote is good, whether a budget is enough, or whether the development is viable.

## Safety

```
USER BUDGET != PROJECT COST
QUOTE != ACTUAL COST
BENCHMARK != PROPERTY FACT
£/sqm != TOTAL £
£/sqm != £/sqft
BASE COST != TOTAL DEVELOPMENT COST
MISSING COST != £0
NO QUOTE != NO COST
LOW COST EVIDENCE != CHEAP PROJECT
```

`renovationCost` remains a **frozen finance input** (`USER_INPUT` / `USER_BUDGET` / `PROJECT_COST_INPUT`). It is not assessed project cost.

## Kinds

`ACTUAL_COST`, `SUPPLIER_QUOTE`, `CONTRACTOR_QUOTE`, `PROFESSIONAL_QUOTE`, `BENCHMARK`, `USER_BUDGET`, `USER_ESTIMATE`, `ASSUMPTION`, `SCENARIO`, `CALCULATED`, `UNKNOWN`.

These are not collapsed. `UNKNOWN` is valid.

## Aggregation

Only explicit compatible items in the same project and scenario, same currency, no duplicate IDs.  
Quotes, actuals, and budgets are totalled separately.  
A quote is excluded from the quote subtotal when an actual exists for the same `scopeId`.  
A subtotal is **not** total project cost unless completeness is `COMPLETE_FOR_DECLARED_SCOPE`.

No automatic contingency, professional fees, VAT, or escalation.

## Boundaries

| Domain | Rule |
|---|---|
| DEVELOPMENT | Scope does not invent cost |
| BUILDING_CONDITION | Defect does not invent cost |
| MAINTENANCE_CAPEX | Remains FUTURE and separate |
| PLANNING / LEGAL / ENVIRONMENT | Dependencies do not invent cost |
| FINANCE | `renovationCost` frozen; project costs are not routed into BTL metrics |
| VALUATION | No cost-driven uplift or discount |
| FEASIBILITY | Not implemented |

## Live wiring

PLANNING and ENVIRONMENT remain the only live specialised domains.  
DEVELOPMENT, LEGAL_TITLE, BUILDING_CONDITION, and PROJECT_COST stay unwired.  
A property without a project does not receive project-cost data.

## Persistence

No current workflow stores quotes, invoices, or project cost items.  
Contracts-only is the correct decision. Speculative tables were not created.
