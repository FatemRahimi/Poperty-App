# V1.2 Phase 9.1 — Private evidence production hardening

Private evidence remains a domain-neutral primitive. This phase hardens storage, safety, lifecycle, and reuse — it does not add Building Condition, surveys, quotes, OCR, or Legal interpretation.

## Storage

| Mode | Provider | Durability | Ingest |
| --- | --- | --- | --- |
| Development / test (`NODE_ENV` not `production`, `PRIVATE_EVIDENCE_PROVIDER=local`) | `LOCAL_PRIVATE` | `DEVELOPMENT_LOCAL` | Allowed. Capability is `DEGRADED`. |
| Production | `PRODUCTION_PRIVATE` only if an implemented backend exists | `DURABLE_PRIVATE` | No backend is implemented in this repository. Ingest is `UNAVAILABLE`. |
| Any other / missing production backend | `UNAVAILABLE` | `UNAVAILABLE` | Fail closed. Never falls back to `/uploads` or silent local disk. |

Consumers use `put` / `read` / `exists` / `delete` / `stat`. They must not depend on filesystem paths.

### Local safety (development)

- Root: `server/private-evidence/` or `PRIVATE_EVIDENCE_ROOT`
- Not mounted on `express.static` (`/uploads` remains public marketing photos only)
- Generated UUID keys only; user filenames are metadata
- Traversal and non-UUID keys rejected
- Symlinks rejected where `lstat` can detect them
- Atomic write: `wx` temp file + rename
- POSIX `0700` / `0600` attempted; **Windows cannot guarantee those modes**
- Cross-platform: symlink creation, chmod, and `realpath` behaviour differ on Windows

Local disk is **not** production-durable.

## Malware / scanning

Accepted types: PDF, JPEG, PNG after extension + declared MIME + magic-byte agreement.

Magic bytes are **not** a malware scanner. Scan state is always `SCAN_UNAVAILABLE` until a real configured scanner exists. `CLEAN` is never claimed.

No malware SaaS is configured. Production ingest is blocked rather than pretending files are trusted.

Development downloads are allowed only because capability is explicitly `DEVELOPMENT_LOCAL` / `DEGRADED`. Production must not use that path.

## Lifecycle

Archive updates the DB row and attempts physical delete.

| Result | `archived` | `deleted` / `bytesRemoved` | `lifecycle_state` |
| --- | --- | --- | --- |
| Row archived and bytes gone | true | true | `ARCHIVED` |
| Row archived, bytes still present | true | false | `DELETE_FAILED` |

Do not treat archive as deletion completed if bytes remain.

Retry: `npm run reconcile:private-evidence` — retries `DELETE_FAILED` only. Never deletes unknown files.

Read-only orphan audit: `npm run audit:private-evidence`

## Access

- `OWNER_ACCESS` — document owner
- `ADMINISTRATIVE_ACCESS` — admin role, intentional and written to `evidence_access_events` (actor, document, action, class, time). No bytes, paths, hashes, or filenames.

Unauthorized read/archive: `404 DOCUMENT_NOT_FOUND`. Same-hash files owned by another user are not revealed.

Public/client document responses omit `contentHash`, storage keys, owner IDs, and paths. Hash remains server-side for owner-scoped dedupe and integrity.

## Legal freshness

The previous one-year “stale register” finding is removed. There is no authoritative methodology for that threshold.

Preserved: `documentDate`, `analysisAt`, optional `documentAges.ageDays`.

`currentRegisterStatus` is `NOT_ASSESSED` unless a genuine freshness methodology exists.

## Configuration

| Variable | Purpose |
| --- | --- |
| `PRIVATE_EVIDENCE_PROVIDER` | `local` (default) or `production` |
| `PRIVATE_EVIDENCE_ROOT` | Local root (dev/test) |
| `PRIVATE_EVIDENCE_MAX_BYTES` | Cap ≤ 20MB |
| `PRIVATE_EVIDENCE_PRODUCTION_BACKEND` | Must match an **implemented** backend. None are implemented. Setting an unknown name does not enable ingest. |
| `NODE_ENV=production` | Fail closed unless a real production backend is implemented |

## Deployment requirements (outside this repository)

- Durable private object store (not public `/uploads`)
- Encryption at rest: **NOT VERIFIED** (host/provider responsibility; no custom crypto)
- Backup of **both** DB rows and object bytes: **NOT VERIFIED**
- Real malware scanner before production ingest
- Secrets never in source, client, snapshots, or logs

## Real-document smoke (authorised user only)

Do not invent legal facts. If no real or intentionally supplied test document is available:

`REAL DOCUMENT SMOKE = NOT EXECUTED`

Procedure when a real document is supplied by an authorised user:

1. Upload via legal-evidence endpoint
2. Confirm public metadata (no hash, no storage key, `scanClean=false`)
3. Analyse — expect `LEGAL_TITLE` `PARTIAL`, `currentRegisterStatus=NOT_ASSESSED`
4. Save snapshot
5. Archive document (`deleted` reflects physical bytes)
6. Reopen snapshot — historical evidence state unchanged

## Reuse gate

Another domain (including Building Condition) may consume this primitive only after the criteria in the Phase 9.1 report pass **and** production storage, scanning, backup, and encryption requirements are met. A stable interface alone is not enough.
